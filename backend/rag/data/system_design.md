# 系统设计面试知识点

## 高并发系统设计

### 流量漏斗
CDN → 负载均衡 → API 网关 → 微服务 → 缓存 → 数据库

### 限流算法
- **令牌桶**：匀速生成令牌，允许突发流量
- **漏桶**：固定速率处理，平滑流量
- **滑动窗口**：更精确，Redis ZSet 实现

### 缓存策略
- Cache Aside（旁路缓存）：读写代码里控制，最常用
- Write Through：写时同时更新缓存和DB
- Write Back：先写缓存，异步刷DB（性能最好，有丢数据风险）

缓存问题：
- 缓存穿透：查不存在的数据 → 布隆过滤器 / 缓存空值
- 缓存雪崩：大量 key 同时过期 → 随机过期时间 + 熔断
- 缓存击穿：热点 key 过期 → 互斥锁 / 永不过期

## 消息队列

作用：削峰填谷、异步解耦、最终一致性

常用：Kafka（高吞吐流处理）、RocketMQ（金融级消息）、RabbitMQ（通用业务）

消息可靠性保证：
1. 生产者确认（ACK）
2. 消息持久化
3. 消费者手动 ACK，失败重试

## 分布式系统 CAP 理论

- **C** 一致性：所有节点同一时刻数据一致
- **A** 可用性：每个请求都有响应
- **P** 分区容错性：网络分区时系统仍运行

CAP 只能同时满足两个。实践中 P 必须保证，因此是 CP（ZooKeeper）或 AP（Eureka/Redis Cluster）的选择。

## 微服务

优点：独立部署、技术异构、故障隔离
缺点：分布式复杂性、网络开销、数据一致性难

服务治理：服务注册发现（Nacos/Consul）、负载均衡、熔断降级（Hystrix/Sentinel）、链路追踪（Zipkin/Jaeger）

## 数据库分库分表

垂直拆分：按业务分库（用户库、订单库）
水平拆分：按 ID 取模或哈希分表

分片键选择原则：离散性高、查询条件常用、不会被修改

问题：跨分片查询复杂、分布式事务、全局唯一 ID（雪花算法）
